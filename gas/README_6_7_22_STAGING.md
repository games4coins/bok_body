# BOK Body 6.7.22 — ранняя бронь и автоматические действия призов (STAGING)

## ВНИМАНИЕ

Это **тестовый комплект**, собранный по выгрузке GAS 23.11.2026 и более позднему исправлению Achievements.js. Не перезаписывайте им действующий GAS без предварительной сверки актуальных файлов через `clasp pull`. Ветка GitHub `feature/early-booking-rewards-6722` не влияет на текущую опубликованную страницу.

## Реализованный проект механики

- Один выигрыш приза `early_booking` = одно право ранней брони ровно **одного** номерка.
- Право используется **только во время паузы** (`paused=ДА`) и только при включённом `BOK_EARLY_BOOKING_ENABLED=true`. В обычном режиме бронирования ничего не меняется.
- Обязательно подтверждение собственного VK ID. Бронирование чужому профилю не позволяет расходовать право.
- Проверки занятости номера, лимитов и замороженного аккаунта сохраняются; расходование проходит под существующим LockService.
- Бронь сохраняет `source='автобронь:<ID права>'`. При сбое после записи брони она всё равно считается использовавшей право, исключая повторную трату.
- Стандартная история `BOK Ачивки` не удаляется и не меняется при расходовании права.
- Действия призов (`none`, `early_booking`, `unlock_achievement`, `reset_misses`, `add_spins`, `grant_gift`) выбираются из белого списка, никакой произвольный JavaScript или формулы из таблицы не исполняются.
- Каждый применённый эффект связан с ID выигрыша; повтор `achSpin` с тем же `requestId` не приводит к повторной выдаче. Для восстановления частично выполненных начислений используются детерминированные ID.
- Автоматическое назначение действует только на выигрыши **после** настройки действия. Для старых невручённых призов «Автобронь» — отдельный административный предварительный просмотр и подтверждаемый перенос.
- Сброс пропусков касается только счётчика, не накопительного баланса. Авторазблокировка выбирает первое неоткрытое положительное достижение из текущего `ACH_DEFS`; если они закончились, автоматической замены призом пока нет.

- `BOK Действия призов`: ID приза / Действие / Параметр / Активно / Включено с
- `BOK Исполнения призов`: ID выигрыша / Дата / Ключ / ID приза / Действие / Результат
- `BOK Права ранней брони`: ID права / Дата / Ключ / ID выигрыша / Использовано / Код брони

Не редактируйте эти журналы вручную. Не удаляйте строки из `BOK Выигрыши` и `BOK Вращения` для сброса тестов.

## Административные действия в Code.js

- `adminRewardRule` — сохраняет действие для выбранного существующего приза.
- `adminRewardRules` — читает настройки действий.
- `adminEarlyBookingSettings` — включает/выключает раннюю бронь, только для администратора.
- `adminEarlyBackfill` — предварительная проверка `apply:false`; фактический перенос требует `apply:true,confirm:'ACTIVATE_EARLY_BACKFILL'`.
- `earlyBookingState` — приватная проверка своего права по подтверждённому VK ID.

Все `admin*` маршруты должны оставаться после `checkAdmin_`, с тем же паролем.

## Безопасный порядок пробного развёртывания

1. Создать **копию Google-таблицы** и **отдельный проект GAS**, не использовать production SS_ID и VK-секреты без необходимости.
2. Сопоставить `GAS/*.js` со свежим `clasp pull`, включая исторические доработки. Проверить отсутствие дублей глобальных функций.
3. Разместить файлы в отдельном тестовом GAS, установить `SS_ID` на тестовую таблицу, перенести необходимые настройки отдельно.
4. Опубликовать тестовый `/exec`, использовать его в `config.js` тестового фронта на отдельной ветке/локальном сервере.
5. В админке на вкладке «Ачивки» выбрать выигрыш «Автобронь номерка до старта» и назначить `early_booking`; иным нужным призам назначить действия.
6. Включить `BOK_EARLY_BOOKING_ENABLED=true` в **тестовом** GAS (либо защищённым админским маршрутом).
7. При `paused=ДА` и `bookingOpen=НЕТ` авторизоваться как владелец выигранного права; выбрать ровно один свободный номерок. Проверить новый код в листе `Брони` и `Использовано=ДА` в правах.
8. Повторить запрос, попытаться выбрать 2 номерка, забронировать на чужого участника, использовать право дважды. Все должны быть отклонены.
9. Проверить синхронизацию обычного эфира, заморозку, лимиты, обычные ачивки, три «Ничего», неуспешное обращение к GAS и повтор `requestId`.
10. Исторические права: сначала `adminEarlyBackfill` с `apply:false`, сверить участников и количество; только затем фактическая миграция с подтверждением.
11. **Только после успешной проверки** перенести точечные изменения в актуальную рабочую версию GAS; сохранить её бэкап и возможность отката.

## Критичные оговорки

- Пока не реализована строгая транзакционная БД; в Google Sheets разные `appendRow` не являются одной атомарной транзакцией. Код рассчитан на безопасное восстановление по повторному идентификатору, но требует интеграционных испытаний на реальных Apps Script/Sheets.
- Автоматические выплаты в рублях/депозитах не внедрены: только вращения (1–20), реальные подарки каталога, достижение, пропуски и ранняя бронь. Денежные бонусы требуют отдельного согласования правил.
- Для старых выигрышей доступен предварительный просмотр и ручной перенос только для активного правила `early_booking`. По умолчанию исторические права не импортируются.
- Призовые действия можно менять в админке, но они вступают в силу для новых выигрышей. Не редактируйте параметры во время вращения.
